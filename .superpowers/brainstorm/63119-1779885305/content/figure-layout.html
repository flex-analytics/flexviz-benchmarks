A — Metrics × Scaling grid

Rows = metric (total/query/transfer/render). Columns = scaling type × source. All variation in one glance.

Pros

  • Everything visible at once
  • Easy to compare a metric across scaling types

Cons

  • Wide figure (16 cols effectively)
  • Subplots can be small

B — Two row-groups (scaling first)

Top block = rows scaling, bottom block = traces scaling. Within each block: columns are source × metric combos.

Pros

  • Visual separation of scaling dimensions
  • Easier to read one scaling story at a time

Cons

  • Comparing same metric across scaling requires vertical scan
  • Column headers get verbose

C — Scaling × Metrics grid (recommended)

Rows = scaling dimension (rows↑, traces↑). Columns = metric × source. Sources stay adjacent; scaling types are immediately comparable top-to-bottom.

Pros

  • Compact — 2 rows read naturally
  • Easy to add memory row beneath each scaling row
  • Per-source comparison stays local

Cons

  • 8 columns — needs a wide figure
